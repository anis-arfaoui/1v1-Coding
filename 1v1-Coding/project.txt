================================================================================
EVALUATION OF THIS SPRINT BREAKDOWN
================================================================================
Why this 5-week breakdown is highly effective in an Agile environment:
1. Progressive Layering:
   - Week 1 builds the user-facing web pages and wireframes (Visual prototype).
   - Week 2 adds the developer workspace and code editing frame (Editor environment).
   - Week 3 establishes the real-time multiplayer pipe connecting 2 players (Networking).
   - Week 4 injects the challenges, execution sandbox, and game rules (Game mechanics).
   - Week 5 polishes, tests, hardens, and ships the application live (Release & QA).
2. Clear Increment at Every Sprint:
   - Each sprint produces a testable, demonstrable milestone for stakeholder reviews.
3. Decoupled Parallelism:
   - Separating the code frame (Sprint 2) from networking (Sprint 3) allows the editor
     to be perfected before wiring it up to WebSockets.

WEEK 3: SPRINT 3 — CONNECT TWO PLAYERS (NETWORKING, ROOMS & COUNTDOWN)
================================================================================

Sprint Goal:
  Build the Node.js + Express + Socket.IO backend, implement the authoritative room
  matchmaking system with 6-character room codes, sync real-time player presence,
  and orchestrate the synchronized 3-2-1 countdown transition.

User Stories:
  - US-3.1: As Player 1, I want the server to generate a unique 6-character room
    code when I create a match.
  - US-3.2: As Player 2, I want to enter the 6-character code and instantly join
    Player 1's lobby.
  - US-3.3: As a player in the lobby, I want to see when the other player connects
    or disconnects in real time without refreshing.
  - US-3.4: As both players, once two players are connected in the lobby, I want
    an animated 3-2-1-DUEL countdown to start automatically on both screens.

Tasks & Implementation:
  1. Backend Server Setup (`server.js`):
     - Express app with CORS middleware and HTTP server.
     - Socket.IO initialization with WebSocket support.
     - In-memory `rooms = new Map()` state container.
  2. Room Code Generator (`generateRoomCode`):
     - Generate collision-free 6-character code from `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`.
  3. Socket Event System:
     - `create_room`: Accepts `{ nickname, difficulty }`. Creates room, joins socket
       channel `socket.join(code)`, emits `room_created`.
     - `join_room`: Accepts `{ roomCode, nickname }`.
       Validates room exists, has < 2 players, and is in `'waiting'` state.
       Emits `error_message` if invalid.
       If valid: adds player 2, joins channel, emits `room_joined` to joiner and
       `player_joined` to room.
     - `disconnect`: Detects socket disconnection; cleans up empty rooms or notifies
       the remaining player.
  4. Frontend Socket Integration (`src/utils/socket.js`, `src/App.jsx`):
     - Connect Socket.IO client to backend server origin.
     - Wire `create_room` and `join_room` actions to HomeScreen buttons.
     - Update `LobbyScreen` live when `player_joined` arrives from server.
  5. Synchronized Countdown System:
     - When Player 2 joins, backend triggers `startCountdown(room)`.
     - Server runs 1-second interval broadcasting `countdown_tick` ({ seconds: 3, 2, 1 }).
     - Build `src/components/CountdownOverlay.jsx`:
       * Fullscreen dramatic animated overlay displaying "3", "2", "1", "DUEL!".
     - When countdown hits 0, server switches room status to `'in_game'` and emits
       `game_start` to both players, transitioning their screens to `DuelScreen`.

Deliverables / Increment:
  Two separate browser windows can create a room, join with a code, see each other
  in the lobby, and trigger a simultaneous 3-2-1-DUEL countdown that opens the duel.

Definition of Done (Sprint 3):
  [x] Backend runs Express + Socket.IO on `http://localhost:3000`.
  [x] 6-character room codes generate without duplicates or ambiguous characters.
  [x] Real-time lobby sync connects Player 1 and Player 2 reliably.
  [x] Error messages display when entering invalid or full room codes.
  [x] 3-second animated countdown starts synchronously on both screens.

WEEK 4: SPRINT 4 — CHALLENGES, TEST & RUN, TIMER & WINNER REFEREE
================================================================================

Sprint Goal:
  Build the problem dataset (`problems.json`), implement the isolated Web Worker
  execution sandbox with 2000ms safety timeout, establish the server-authoritative
  timer and hint dispatcher, track live opponent progress, and implement the winner
  referee and Game Over / Rematch modal.

User Stories:
  - US-4.1: As a player, I want to receive a real JavaScript problem from the problem
    bank with starter code and test cases.
  - US-4.2: As a player, I want to click "Run & Test" and safely execute my code
    in an isolated Web Worker without freezing my browser on infinite loops.
  - US-4.3: As both players, I want a server-controlled countdown timer and automatic
    hints unlocking at 1/3 and 2/3 of match duration.
  - US-4.4: As a player, I want to see my opponent's live progress bar update when
    they pass tests.
  - US-4.5: As a player, the first person to pass 100% of test cases should win
    immediately with celebration confetti; if time runs out, it's a draw; if an
    opponent disconnects, I win by forfeit.
  - US-4.6: As both players, I want a "Request Rematch" button to immediately play
    another challenge together.

Tasks & Implementation:
  1. Problem Dataset (`problems.json`):
     - Create 11 coding challenges across Easy, Medium, and Hard difficulties.
     - Include `id`, `title`, `difficulty`, `timeLimit`, `description`, `example`,
       `hints` (array), `starterCode`, and `tests` (input/output array).
  2. Web Worker Execution Sandbox (`public/runner.js`):
     - Create worker thread to isolate code execution.
     - Implement `isDeepEqual(a, b)` for deep value comparison.
     - Intercept `console.log` statements to capture user debugging output.
     - Measure per-test execution time in milliseconds (`performance.now()`).
     - Deep clone inputs so user code cannot mutate test fixtures.
  3. Timeout Guard (`src/utils/codeRunner.js`):
     - Spawn worker with strict 2000ms safety timeout (`setTimeout`).
     - Terminate worker (`worker.terminate()`) if code hangs (e.g. `while(true)`),
       returning an execution timeout error.
  4. Authoritative Server Timer & Hints (`server.js`):
     - In `startGame(room)`: select problem matching room difficulty, start 1s interval.
     - Emit `timer_tick` ({ timeRemaining, totalTime }).
     - Unlock Hint 1 at 2/3 time remaining (1/3 elapsed); emit `hint_unlocked`.
     - Unlock Hint 2 at 1/3 time remaining (2/3 elapsed); emit `hint_unlocked`.
     - When time hits 0: emit `game_over` with `result: 'draw'`.
  5. Live Opponent Progress Broadcast:
     - On code run: client emits `player_progress` ({ roomCode, testsPassed, totalTests }).
     - Server relays `opponent_progress` to the other player.
     - DuelScreen renders live animated opponent progress bar.
  6. Authoritative Winner Detection & Disconnection Referee:
     - When client passes 100% of tests, emit `solved` event.
     - Server single-threaded event loop locks the win atomically for the first
       valid submission: marks room `game_over`, clears timer, broadcasts `game_over`
       ({ result: 'win', winnerNickname, elapsedSeconds }).
     - If a player disconnects mid-game: award immediate forfeit victory to remaining player.
  7. Game Over Modal & Rematch Flow (`GameOverModal.jsx`):
     - Outcome banner (Victory, Defeat, Draw, Forfeit).
     - Confetti explosion using `canvas-confetti` for the winner.
     - "Request Rematch" button emitting `play_again`.
     - When both players request rematch, backend automatically picks a new problem
       and triggers a fresh 3-second countdown.

Deliverables / Increment:
  A fully playable multiplayer coding duel game where two players receive challenges,
  write code, execute tests safely, receive hints, race against the timer, and
  experience instant win/draw/forfeit/rematch resolution.

Definition of Done (Sprint 4):
  [x] 11 problems with verified tests loaded from `problems.json`.
  [x] Web Worker executes code safely and kills infinite loops after 2 seconds.
  [x] Server controls timer ticks and unlocks hints at 1/3 and 2/3 elapsed time.
  [x] Opponent progress bar updates live across sockets.
  [x] First player to pass all tests wins; timeout results in a draw; disconnects forfeit.
  [x] Game Over modal renders outcome and supports rematching with a new problem.

WEEK 5: SPRINT 5 — OPTIMIZATION, AUTOMATED E2E TESTING, AUDIO & DEPLOYMENT
================================================================================

Sprint Goal:
  Implement an automated end-to-end integration test suite, harden edge cases
  and memory cleanup, synthesize retro 8-bit sound effects using the Web Audio API,
  optimize the production build, and deploy the application live to cloud hosting.

User Stories:
  - US-5.1: As a developer, I want an automated test suite verifying problem schemas,
    code execution, and dual-client socket flows.
  - US-5.2: As a player, I want synthesized retro sound effects for countdowns,
    runs, hints, victory, and defeat with a mute toggle.
  - US-5.3: As a user, I want the web app to load quickly, handle bad inputs
    gracefully, and never crash.
  - US-5.4: As a player, I want the game hosted live on the web so I can duel
    my friends on different devices anywhere in the world.

Tasks & Implementation:
  1. Automated Integration Test Suite (`test/duel.test.js`):
     - Problem schema validation (check all 11 problems have required fields).
     - Test runner simulation: verify correct code passes and incorrect code fails.
     - Dual-client Socket.IO integration test:
       * Client A creates room; Client B joins room.
       * Verify countdown tick and game start events.
       * Client A emits progress -> verify Client B receives opponent progress.
       * Client A emits solved -> verify game over win is broadcast.
     - Add `npm test` script to `package.json`.
  2. Edge Case Hardening & Defenses:
     - Sanitize nicknames (trim whitespace, fallback to "Player 1" / "Player 2").
     - Normalize room codes to uppercase and strip spaces.
     - Guard against duplicate submissions after match completion.
     - Room cleanup: clear all intervals (`clearInterval`) on game over or disconnect
       to eliminate server memory leaks.
     - Deep clone inputs in runner to prevent test fixture corruption.
  3. Synthesized Retro Audio Engine (`src/utils/audio.js`):
     - Pure Web Audio API oscillators (sine, square, triangle wave synthesis).
     - Sound effects: Countdown beeps (440Hz -> 880Hz), game start fanfare, test pass chime,
       test fail buzz, hint unlock chime, victory fanfare, and defeat minor chords.
     - Audio mute toggle in Header with persistent `localStorage` preference.
  4. Production Build & SPA Fallback Serving:
     - Configure Vite production bundling to `dist/`.
     - Configure Express in `server.js` to serve static assets from `dist/`.
     - Implement SPA wildcard fallback (`app.get('*', ...)`) to serve `index.html`.
     - Add `/api/health` monitoring route returning server status and active rooms.
  5. Cloud Deployment (Render / Railway):
     - Set up cloud web service with Node.js environment.
     - Configure build command: `npm install && npm run build`.
     - Configure start command: `npm start`.
     - Test live WebSocket connectivity between mobile and desktop devices.
  6. Final Documentation & Presentation:
     - Update `README.md` with architecture diagrams, play guide, and deployment steps.
     - Prepare demo script for final sprint presentation.

Deliverables / Increment:
  A production-ready, fully tested, hardened, and sound-equipped web application
  deployed live online and playable across devices.

Definition of Done (Sprint 5):
  [x] Automated test suite in `test/duel.test.js` passes 100%.
  [x] Infinite loops, bad inputs, and disconnections handled gracefully.
  [x] Synthesized Web Audio API sound effects work with mute toggle.
  [x] Production build passes cleanly with zero warnings or errors.
  [x] Application is deployed live on Render / Railway and playable over the internet.
  [x] Complete `README.md` documentation and presentation demo ready.

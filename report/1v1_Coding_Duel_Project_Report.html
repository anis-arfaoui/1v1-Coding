Introduction

Motivation

In contemporary computer science education and professional hiring, the capacity to formulate algorithmic solutions efficiently, accurately, and under rigorous time constraints has emerged as a fundamental skill. A diverse ecosystem of online coding platforms—such as LeetCode, HackerRank, and Codewars—has established industry-standard practices for individual practice, asynchronous skill assessments, and algorithm exploration.

However, these conventional platforms inherently focus on solitary, asynchronous evaluation. When an individual submits a solution, code is graded against a test suite in isolation, and results are delivered without peer interaction. This model lacks the visceral engagement, peer accountability, and adrenaline of synchronous, head-to-head competitive racing. In a live scrimmage against a friend, peer, or colleague:

  • Contestants do not experience the psychological pressure of seeing an opponent rapidly pass test cases in real time.
  • Users must navigate cumbersome account registrations, multi-step authentications, and complex organization workspaces before typing a single line of code.
  • Shared countdown clocks, live progressive hints, and synchronized instant victory celebrations are absent.

1v1 Coding Duel directly addresses these deficiencies. By offering an arcade-style, zero-barrier web arena where two developers can enter a room with a 6-character code, receive the same algorithmic problem, and race side-by-side to solve it before the clock strikes zero, the platform transforms algorithmic problem-solving into a dynamic, highly social esport.

Scrum as an Agile Methodology

Building a real-time multiplayer application with live WebSockets, browser-sandboxed code execution, synchronized audio, and reactive user interfaces requires managing multiple interdependent technical risks. To prevent the delays, misaligned integrations, and inflexibility typical of traditional "Waterfall" models, our team employed the Scrum framework under Agile principles.

Scrum organizes work into focused, iterative cycles known as Sprints, anchored by three fundamental pillars:

  • Transparency: All user stories, architectural diagrams, task states, and socket protocols were centrally maintained in Jira and GitHub, providing complete visibility across the team.
  • Inspection: At the close of every sprint, the working software increment was rigorously tested and demonstrated in real browser environments against strict acceptance criteria.
  • Adaptation: When technical hurdles occurred—such as browser thread freezing during infinite user loops or race conditions in simultaneous socket submissions—the team promptly refined the backlog and adjusted technical strategies.

Chapter 1: Case Study & Project Specifications

1.1 Context and Project Definition

1v1 Coding Duel is a lightweight, responsive web application engineered to facilitate real-time competitive programming duels between two participants over standard web browsers. It eliminates the barrier of software installation, user registration, and manual room coordination by offering an instantaneous, URL-driven matchmaking experience.

The architecture unites an authoritative Node.js + Express backend with a real-time Socket.IO synchronization layer, a browser-based CodeMirror 6 code editor, and an isolated Web Worker execution sandbox. By keeping the server authoritative over game rules (match timers, hints, and winner declarations) while executing code client-side inside Web Workers, the system achieves instant responsiveness with zero server CPU execution overhead.

1.2 Project Objectives

  1. Frictionless Onboarding: Enable any developer to launch a room, configure challenge parameters, and share an invite link in under 10 seconds without credential storage or login forms.
  2. Deterministic Synchronization: Guarantee both players receive the identical problem description, starting template, and test suite simultaneously, with millisecond-accurate timer ticks.
  3. Safe In-Browser Execution Sandbox: Securely evaluate user-submitted JavaScript within an isolated browser Web Worker, equipped with a 2000ms safety timeout guard to terminate accidental infinite loops (`while(true)`) without freezing the user's interface.
  4. Authoritative Game Management: Prevent client-side cheating by enforcing problem selection, countdown initiation, progressive hint delivery, and win/loss refereeing on the server.
  5. Rich Retro Audio Feedback: Provide synthesized retro 8-bit sound effects using the native browser Web Audio API, avoiding external media file network dependencies.

1.3 Project Scope & Target Users

The primary audience encompasses university students, interview candidates, hackathon participants, and programming clubs. The system targets desktop and laptop devices with modern evergreen web browsers (Google Chrome, Mozilla Firefox, Microsoft Edge, Apple Safari). The problem domain is scoped to algorithmic JavaScript challenges, focusing on data structures, array manipulation, string algorithms, recursion, and mathematical computation.

1.4 Functional Description of Requirements

The system's functional architecture is decomposed into six cohesive modules:

1.4.1 Room Creation & Matchmaking Module

  • Host Room Generation: Allows any user to generate a match by specifying a nickname and difficulty level (`Any`, `Easy`, `Medium`, `Hard`). Generates a collision-resistant 6-character room code.
  • Guest Join: Allows a second player to enter a match by typing the 6-character code or navigating directly through a query string link (`?join=CODE`).
  • Room Capacity & State Guard: Restricts rooms strictly to 2 players; immediately rejects excess joiners or attempts to enter games in progress.
  • Presence Tracking: Live status indicators update dynamically when players connect, disconnect, or leave.

1.4.2 In-Browser Code Editor & IDE Module

  • CodeMirror 6 Engine: Full JavaScript syntax highlighting, line numbering, active line highlight, and automatic bracket closure.
  • Code Reset Action: Allows the player to reset their editor buffer to the default starter function signature (`function solve(...)`).
  • Keyboard Shortcuts: Supports `Ctrl + Enter` (or `Cmd + Enter` on macOS) to instantly run test suites.

1.4.3 Isolated Execution Sandbox & Test Runner Module

  • Web Worker Threading: User code executes inside an isolated background Web Worker (`public/runner.js`), separating untrusted user code execution from the browser's main UI thread.
  • 2000ms Safety Timeout Guard: A hardware timeout terminates runaway loops (`worker.terminate()`), displaying an informative timeout error.
  • Deep Equality Engine: Implements comprehensive structural comparison (`isDeepEqual`) verifying primitive values, nested arrays, and objects.
  • Console Log Interception: Overrides `console.log` inside the sandbox to capture and present user debugging statements in a dedicated console terminal tab.

1.4.4 Authoritative Gameplay & Synchronized Referee Module

  • Synchronous 3-2-1 Countdown: Triggers a dramatic full-screen countdown overlay on both screens upon second player connection.
  • Server-Authoritative Clock: An internal 1-second server interval emits synchronized `timer_tick` events, turning red during the final 60 seconds.
  • Progressive Hint Dispatch: The server automatically broadcasts Hint 1 at 1/3 elapsed time and Hint 2 at 2/3 elapsed time.
  • Live Opponent Progress: Emits `player_progress` whenever a contestant runs their code, updating the opponent's live progress bar.
  • Authoritative Win Referee: Atomically registers the first valid `solved` submission, stops the timer, and emits `game_over` to declare the winner.
  • Disconnection & Forfeit: If a player disconnects during an active duel, the server immediately awards a forfeit win to the remaining participant.
  • Rematch System: Both players can request a rematch; upon mutual agreement, a new problem is selected and a fresh countdown begins.

1.4.5 Problem Bank Catalog Module

  • Maintains 11 algorithmic challenges stored in structured JSON schema format (`problems.json`), distributed across Easy (5 min), Medium (10 min), and Hard (15 min) tiers.

1.4.6 Synthesized Audio Engine Module

  • Synthesizes dynamic audio cues (countdown ticks, start fanfare, test pass chime, test fail buzz, victory fanfare, defeat chord) via pure Web Audio API oscillators without external asset files. Includes a persistent mute toggle in the header.

Sprint 1 Deliverables & Code Artifact:

The key technical accomplishment was the disambiguated room code generation utility (`src/utils/roomCode.js`), preventing confusing alphanumeric characters (`0`, `O`, `1`, `I`, `L`): 

// src/utils/roomCode.js
const CHARS = 'ABCDEFGHJKLMNPQRSTUVWXYZ23456789';

export function generateRoomCode() {
  let code = '';
  for (let i = 0; i < 6; i++) {
    code += CHARS.charAt(Math.floor(Math.random() * CHARS.length));
  }
  return code;
}

export function isValidRoomCode(code) {
  if (!code || typeof code !== 'string') return false;
  return /^[A-Z0-9]{6}$/.test(code.trim().toUpperCase());
}

Web Worker Sandboxing Architecture & Infinite Loop Guard:

Client-side JavaScript code execution presents a critical stability risk: if user code enters an infinite loop (`while(true)`), it blocks the browser's single-threaded event loop, freezing the interface and crashing the tab. To eliminate this vulnerability, the system encapsulates execution inside a dedicated Web Worker (`public/runner.js`) coupled with a hardware termination guard: 

// src/utils/codeRunner.js
export function runTestsInWorker(userCode, testCases) {
  return new Promise((resolve) => {
    const worker = new Worker('/runner.js');
    let hasReturned = false;

    // Strict 2000ms safety timeout guard
    const timeoutId = setTimeout(() => {
      if (!hasReturned) {
        hasReturned = true;
        worker.terminate(); // Forcefully kills the worker execution thread
        resolve({
          passed: false,
          results: [],
          error: 'Execution Timed Out (2000ms limit). Check for infinite loops or deep recursion!'
        });
      }
    }, 2000);

    worker.onmessage = (e) => {
      if (!hasReturned) {
        hasReturned = true;
        clearTimeout(timeoutId);
        worker.terminate();
        resolve(e.data);
      }
    };

    worker.postMessage({ userCode, testCases });
  });
}

Authoritative Match Referee & Win Detection:

To prevent race conditions when two players submit solutions almost simultaneously, the Node.js event loop acts as an atomic transaction referee. When a client passes all test cases, it emits `solved`: 

// server.js (Authoritative Referee Logic)
socket.on('solved', ({ roomCode }) => {
  const room = rooms.get(roomCode);
  if (!room || room.status !== 'in_game') return;

  // Atomically lock win for first valid submission
  room.status = 'game_over';
  if (room.timerInterval) clearInterval(room.timerInterval);

  io.to(roomCode).emit('game_over', {
    result: 'win',
    winnerId: socket.id,
    winnerNickname: player.nickname,
    elapsedSeconds: room.totalTime - room.timeRemaining
  });
});

Chapter 4: Agile Scrum Evaluation & Conclusion

4.1 Evaluation of Scrum in 1v1 Coding Duel

Adopting the Scrum framework was instrumental to the successful completion of the 1v1 Coding Duel project within the rigorous 5-week schedule:

  • De-risked Progressive Layering: Isolating the visual interface (Sprint 1), code editor (Sprint 2), real-time WebSockets (Sprint 3), and execution sandbox (Sprint 4) prevented catastrophic late-stage integration blockers.
  • Early Elimination of Technical Blockers: Sandbox execution risks (browser thread freezing and untrusted code execution) were analyzed in Sprint 1 and resolved via Web Worker architecture in Sprint 4.
  • Cross-Functional Accountability: Daily 10-minute standups fostered continuous communication between the frontend React layer and the Socket.IO backend event payloads.

4.2 Velocity, Team Synergy & Retrospective Insights

Over the 5 sprints, the team sustained an average velocity of 15.2 story points per sprint. Retrospective meetings produced high-impact adjustments:

  • Sprint 1 Retro: Recognized that ambiguous characters (`0` vs `O`, `1` vs `I`) generated user errors during match joining, leading to the creation of `roomCode.js` with disambiguated character sets.
  • Sprint 3 Retro: Added deep cloning to test inputs in the Web Worker runner to prevent user code from mutating test fixtures across test cases.

4.3 Future Perspectives & Strategic Roadmap

  1. Server-Side Multi-Language Execution: Integrate third-party sandboxed runtimes (such as Piston or Judge0) to support Python, C++, Java, and Rust.
  2. Persistent User Profiles & ELO Ratings: Implement user authentication and persistent matchmaking ratings (ELO) for ranked competitive ladders.
  3. Spectator Mode: Enable non-playing peers to join matches as spectators via read-only WebSocket channels to stream live code typing during tournaments.
